API v1

Use the API

Send the token as a bearer credential with every request:

Authorization: Bearer <token>

Endpoints

GET /api/v1/presentations
List presentations.
POST /api/v1/presentations
Create a presentation.
GET /api/v1/presentations/{slug}
Read a presentation and its Markdown source.
PATCH /api/v1/presentations/{slug}
Update its title, source, or theme. Slugs are immutable.
DELETE /api/v1/presentations/{slug}
Delete it unless a live session is active.

Upload a presentation

Save the generated deck as presentation.json:

{
  "title": "Reliable Rust services",
  "slug": "reliable-rust-services",
  "source": "# Reliable Rust services\n\nOne idea per slide.\n\n---\n\n# Start with failure modes",
  "theme": {
    "font": "system",
    "background": "#1e1e2e",
    "text": "#cdd6f4",
    "accent": "#f9e2af"
  }
}
curl --fail-with-body \
  --request POST \
  --url "$SLIDES_URL/api/v1/presentations" \
  --header "Authorization: Bearer $SLIDES_API_TOKEN" \
  --header "Content-Type: application/json" \
  --data @presentation.json

The slug and theme fields are optional. If omitted, the server derives a unique slug and uses the default theme.

Update Markdown

curl --fail-with-body \
  --request PATCH \
  --url "$SLIDES_URL/api/v1/presentations/reliable-rust-services" \
  --header "Authorization: Bearer $SLIDES_API_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"source":"# Revised deck\n\nUpdated content."}'

Create and source updates validate Slides Markdown before saving. JSON errors include a stable error.code and human-readable error.message.
